# 릴리즈 폴더 이름 규칙

> [메인 지시서](../CLAUDE.md)의 하위 문서. `D:\game\.latest`처럼 아직 앱에 등록하지 않은 게임 릴리즈 폴더를 정리할 때 따르는 이름 규칙을 정리한다. 앱 자체의 기능이 아니라 **사용자가 게임 폴더를 내려받아 정리하는 작업 방식**에 대한 문서다.

## 배경

`D:\game\.latest`는 아직 game-platform에 등록하지 않은(= `games.json`에 없는) 게임 릴리즈 폴더를 모아두는 자리다. 토렌트/공유 사이트에서 받은 폴더 이름은 제각각(대소문자, 구분자, 버전 표기 방식이 배포자마다 다름)이라, 앱에 등록하기 전에 아래 규칙으로 이름을 통일해서 정리한다. `D:\game` 바로 밑의 이미 등록된 게임 폴더들은 이 규칙과 무관하게 각자 등록 당시 이름을 그대로 쓴다(등록된 게임의 폴더 이름을 바꾸려면 정보 창의 "게임 폴더 이름 변경..." 기능을 쓴다 — [게임 관리](game-management.md) 참고).

## 규칙

1. **대소문자**: 폴더 이름 전체에서 **첫 글자만 대문자, 나머지는 전부 소문자**. 하이픈으로 나뉜 각 단어를 대문자로 시작하지 않는다 (예: `A-wife-and-mother-part2-v0.170`, `Bare-witness-v0.5`).
2. **구분자는 하이픈(`-`)만 쓴다**: 점(`.`)이나 밑줄(`_`)로 단어를 나눈 경우 전부 하이픈으로 바꾼다 (`Dmd.ch1` → `Dmd-ch1`, `Girlfriend_eng` → `Girlfriend-eng`). 버전 숫자 안의 점(`v0.14.1`처럼 버전 자릿수를 나누는 점)은 그대로 둔다.
3. **붙어 있는 단어는 하이픈으로 분리한다**: `Barewitness` → `Bare-witness`, `Livetofight` → `Live-to-fight`, `Yakuzarogue` → `Yakuza-rogue`처럼 만들어진 합성 제목은 단어 경계에 하이픈을 넣는다. 단, `housewife`/`roommate`/`summertime`처럼 원래 영어에서도 한 단어로 쓰는 진짜 합성어는 쪼개지 않는다.
4. **버전 번호는 `-v숫자[.숫자...]` 형식**:
   - `v`는 항상 소문자, 항상 앞에 하이픈이 있어야 한다.
   - 버전 숫자만 있고 `v`가 없는 경우(`0.9.4`, `1.0` 등) `v`를 붙인다.
   - 버전 숫자 뒤에 구분자 없이 바로 붙는 글자(`0.96b`, `1.6f`처럼 리비전 표시)는 버전의 일부로 보고 그대로 붙여 둔다 — 단, 그 글자가 아래 5번의 "제거 대상 단어"에 해당하면(`fix4`, `beta58` 등) 제거한다.
   - 버전 숫자 뒤(원래 `v` 없는 상태였을 때)에 따라오던 텍스트는 새로 붙이는 `v` **앞으로** 옮긴다: `Name-0.5-pc` → `Name-pc-v0.5`.
5. **버전 뒤에 붙는 태그 단어는 제거한다**: `kor`, `pc`, `fix`(`fix1`, `fix4` 등 숫자 붙은 것 포함), `ex`, `dlc`, `extra`/`extras`, `fixed`, `elite`, `final`(단독 세그먼트 또는 `the-final` 구문), `extended`, `reworked`, `beta`(`beta58` 등 빌드 번호 포함) — 이런 단어는 언어/플랫폼/패치 표시일 뿐 게임을 구분하는 정보가 아니므로 지운다. 여러 단어가 이어져 있으면(`kor-keep3`, `extra-pc`) 해당 단어만 지우고 나머지는 남긴다.
   - **예외**: 지우면 다른 폴더와 이름이 완전히 같아지는 경우, 그 폴더들은 지우지 않고 원래 이름을 그대로 둔다 (예: `A-wife-and-mother-part2-v0.170-kor`와 `-pc`가 둘 다 있으면 둘 다 그대로 둔다).
6. **구조 표시 축약형**: `sN`(시즌/`season-N`, `sN`, `season N` 전부 이 형태로), `epN`(에피소드/`episode-N`), `pN`(파트/`part-N`) — 글자와 숫자 사이에 하이픈 없이 붙인다 (`season2` → `s2`, `episode-10` → `ep10`, `part-8` → `p8`).
7. **괄호·잡다한 특수문자는 정리**: `v1.0.2c(extra)`처럼 괄호로 묶인 부가 정보는 괄호를 없애고 필요한 내용만 하이픈으로 연결한다.
8. **충돌 방지**: 위 규칙을 적용했을 때 서로 다른 두 폴더 이름이 같아지면, 그 규칙은 그 폴더들에 한해 적용하지 않고 원래 이름을 그대로 둔다. 정보 손실(어떤 폴더인지 구분이 안 되는 상태)보다 약간의 스타일 불일치가 낫다.
9. **안전하게 알 수 없는 이름은 억지로 고치지 않는다**: `RJ01164204`처럼 상품 코드뿐이라 실제 게임 제목을 알 수 없거나, 날짜처럼 실제로 폴더를 구분해주는 정보가 포함된 긴 이름은 그대로 둔다.

## 일괄 변경 시 주의사항

- **작업 직전에 폴더 목록을 다시 읽는다.** 사용자가 같은 폴더를 손으로 직접 정리하는 경우가 있어([[project-dgame-latest-manual-edits]] 메모리 참고), 대화 중 앞서 봤던 이름이 이미 바뀌어 있을 수 있다. 변경 계획을 실행하기 직전에 항상 `Get-ChildItem`으로 실제 현재 이름을 다시 확인한다.
- **이름만 바꾸는 대소문자 변경은 Windows에서 한 번에 안 된다** — NTFS가 대소문자를 구분하지 않아 `Rename-Item`이 "이미 있음"으로 실패할 수 있으므로, 임시 이름을 한 번 거쳐(`A` → `__tmp__` → `a`) 두 단계로 바꾼다.
- **실행 전에 충돌을 미리 확인한다**: 변경 후 이름이 겹치는 폴더가 있는지, 대상 이름이 이미 존재하는지 먼저 검사하고, 겹치는 것은 계획에서 제외한 뒤 나머지만 적용한다.
- 이 문서의 규칙은 [메인 지시서](../CLAUDE.md)의 "실제 사용자 데이터를 건드리는 코드를 검증할 때" 규칙과는 별개다 — 여기서 다루는 `D:\game\.latest` 폴더 이름 변경은 코드 테스트가 아니라 사용자가 직접 요청한 실제 파일 정리 작업이지만, 실제 데이터를 다루는 만큼 같은 수준의 주의(되돌리기 전 확인, 와일드카드 삭제 금지 등)가 적용된다.
